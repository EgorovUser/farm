### 2.2 equip/unequip + событие (§2.3, D21/D30) — ГОТОВО

- `equipment.ts` — `EquipService.equip/unequip` над `(state, ctx)`: чистые проверки (slotById / fitsSlot / занятость / уже-экипирована / гейт) + применение через setState (паттерн сервисов M01). Порядок проверок equip: слот → запись → уже-экипирована → занятость → тип → требования (все отказы с причиной).
- **D30 исполнен полностью**: записи экипированных остаются в `items[]`; `equipped: Record<slotId, iid>` — ссылочная карта (поле D18 заполняется этим сеансом); экипированные не занимают вместимость (`usedSlots`/`info`/`applyPlacement` считают по рюкзаку), не видны в `inv list`, не участвуют в выборе изъятия (`planRemoval(items, defId, qty, equippedIidSet)`); изъятие экипированного — отказ «сначала снимите» при нехватке незэкипированных; unequip возвращает запись в рюкзак даже сверх capacity (легально по D28); экипировка записи ЦЕЛИКОМ (стак наживки ×30 одной записью — selftest); занятый слот — отказ с причиной, авто-подмены нет.
- **Событие `item.equipped`** — ровно одно на экип, payload `{ defId, iid, slot, quality }` (quality включена по D29-правилу «опциональна» — подписчики её наличие НЕ предполагают; канон — API инвентаря). **Unequip — БЕЗ события** (D21): смена состояния + `invalidate.stat` — прецедент M01 (levelUp → invalidate.stat без записи в eventsPublished, сервисное событие каталога 02 §4).
- **Пробы** (копипасты живьём):
  - equip: лента → `15:48:01  item.equipped          {"defId":"iron_sword","iid":"iron_sword#1","slot":"weapon","quality":{"tier":"D","value":3…` — ровно одно;
  - unequip: `inv unequip weapon` → `снято: Железный меч (iron_sword#1) ← слот weapon` — item.* в ленте нет, invalidate.stat опубликован (selftest: «unequip: БЕЗ события (лента item.* пуста) + invalidate.stat опубликован (D21)» ✓);
  - resolve до/после: 5 → (equip) 17 → (unequip) 5 — кэш сбрасывается сразу (интеграционный карточки §7);
  - инварианты D30 — selftest: невидимость (inv list без экипированного), вместимость (used 2→1 после экипа одной из двух записей), remove-отказ « — ещё 1 экипировано, сначала снимите», возврат сверх capacity (рюкзак 20/20 → unequip → 21/20).

### 2.4 equipmentProvider (§2.5; D22/D31) — ГОТОВО

- `provider.ts` — `EquipmentProvider implements ModifierProvider`, id **`inventory.equipment`**; зарегистрирован в манифесте `modifierProviders: ['inventory.equipment']` и в StatBus при activate (снятие — deactivate). Оп-маппинг **D31**: `baseStats` → **flat** (source kind `'item'`, refId = iid), `rolledMods` → **inc** через `ModTypeDef.stat` (значение — процент, отрицательное = дебаф). Модификатор-ids читаемы для трассировки: `item.<iid>.base.<stat>` / `item.<iid>.roll.<modType>`.
- **Сломан-гейт D22**: `durability.current = 0` → предмет НЕ даёт модов (остаётся в слоте, не исчезает): «СЛОМАН (ремонт — M09)» в inv list/info и UI-панели.
- `invalidate.stat` при каждой смене экипировки (equip/unequip) и dev-штампах; кэш резолва сбрасывается сразу (проба resolve до → equip → resolve новый).
- **Пробы** (копипасты живьём, оракулы руками):
  - до экипа: `resolve combat.attack` → `combat.attack = 17` — база **5** (кулаки, content/balance/bases.ts) + flat **12** (baseStats меча) = **17** ✓;
  - `inv mod iron_sword#1 atk_power 25` → `штамп мода: atk_power +25 → iron_sword#1 (from: initial)`, затем `resolve combat.attack` → `combat.attack = 21` — 17 × (1 + 25/100) = 21.25 → round **21** ✓;
  - `inv dur iron_sword#1 0` → `прочность iron_sword#1: 0/80 — СЛОМАН (ремонт — M09)`, затем `resolve combat.attack` → `combat.attack = 5` — модов нет, базе ✓;
  - `inv dur iron_sword#1 80` + `inv unequip weapon` → `combat.attack = 5` — снятие возвращает моды к базе ✓;
  - после F5 (провайдер жив): `combat.attack = 21` ✓.
