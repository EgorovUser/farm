   182→### CRIT-1 · КРИТИЧЕСКИЙ — removeInternal: порча данных при изъятии ≥2 записей (нарушение «потери данных», D25/D28-контекст; M02.3-отчёт заявление «без потерь» — опровергнуто)
   183→
   184→**Корень** (`src/game/modules/inventory/store.ts`, removeInternal, строки 262-267): `drop` собирается в порядке `plan.takes` — **по качеству** (худшие вперёд, D25), а не по индексам записей; затем `drop.reverse()` + последовательные `splice(i, 1)` предполагают порядок по индексам. Когда худшая из изымаемых записей стоит в `items[]` **позже** лучшей (drop убывающий), reverse делает его возрастающим: первый splice сдвигает массив, второй промахывается — запись-цель остаётся зомби с qty=0, а по сдвинутому индексу вырезается **посторонняя запись**.
   185→
   186→```ts
   187→for (const t of plan.takes) {              // порядок по КАЧЕСТВУ (худшие вперёд)
   188→  items[t.index].qty -= t.take;
   189→  if (items[t.index].qty <= 0) drop.push(t.index);
   190→}
   191→for (const i of drop.reverse()) items.splice(i, 1);   // ← предполагает индексный порядок
   192→```
