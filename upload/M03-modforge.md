# M03 — Ривен-генератор: конструктор характеристик по бюджету

> Фаза 1 · объём L (3 подзадачи) · вход: 01-CORE, 02-BUSES, 03-DATA, M02, этот файл.
> РЕФЕРЕНС: система модов разломов Warframe (Riven). Это УНИВЕРСАЛЬНЫЙ движок: он не знает, кому роллит — кирке, карточке заточки, трейту работника или помощнику. Все просто вызывают `rollFor(...)` со своим бюджетом и тегами.

## 1. Цель модуля

Один движок, который собирает характеристики любой сущности «из конструктора»: получает список типов характеристик (`ModTypeDef`), их кривые стоимости, бюджет — и набирает в бюджет случайную комбинацию бафов и дебафов. Каждому бафу рассчитывается ПОЛОЖИТЕЛЬНАЯ стоимость, каждому дебафу — ОТРИЦАТЕЛЬНАЯ (дебаф возвращает бюджет). Система обязана работать с любыми будущими типами характеристик, добавленными в реестр данными (принцип «неизвестности» 01-CORE П5).

## 2. Реестр типов характеристик

`content/mods/registry.ts` — таблица `ModTypeDef` (03-DATA §5): тип, целевой стат шины, теги применимости (`tool`, `weapon`, `rod`, `worker`, `helper`, `card:forge`, `building`), диапазоны `maxPositive`/`maxNegative`, вес стоимости, кривая. Примеры строк:

| id | stat | применимость | maxPositive | maxNegative |
|---|---|---|---|---|
| `oreYield` | `mine.oreYield` | tool/pickaxe, card:forge | +25% | — |
| `growthSpeed` | `farm.growthSpeed` | tool/hoe, card:forge | +15% | −10% |
| `energyCostReduction` | `action.*.energyCost` | card:forge, worker | −25% | +10% |
| `rarityLuck` | `fishing.luck.rare` | rod, bait | +40% | −20% |
| `crit` | `mine.crit` | weapon, card:forge | +10% | — |
| `blockSense` | `mine.blockSense` | shield, card:forge | +12% | — |
| `maxDurability` | `item.durability.max` | tool/weapon/armor | +30% | −15% |
| `workerSpeed` | `worker.<sys>.speed` | worker | +20% | −10% |
| `forgeCost` | `forge.cost` | card:forge | −15% | +20% |
| `treasureBias` | `fishing.treasure.weight` | rod | ×4 | — |

Добавление новой характеристики = новая строка реестра, ноль кода.

## 3. Стоимость характеристик

```
costPositive(v) = round( costWeight × (v / maxPositive)^1.35 × 100 ) / 100     // суперлинейно: у максимума дорого
costNegative(v) = − round( costWeight × (|v| / maxNegative)^0.9 × 100 ) / 100  // почти линейно
```

Правило бюджета: `Σ positive costs − Σ |negative costs| × refundRate ≤ budget`, где `refundRate = 1.25` (дебаф «возвращает» в бюджет больше, чем реально отнимает — так слабые дебафы становятся выгодными и встречаются у сильных роллов, как в Warframe).

## 4. Бюджеты

`content/balance/modforge.ts` (`ModBudgetRule`, 03-DATA §5). СТАРТОВЫЕ ЗНАЧЕНИЯ:

| Редкость/источник | Бюджет | Кол-во бафов | Шанс дебафа |
|---|---|---|---|
| common | **10** | 1 | 0% |
| uncommon | 16 | 1–2 | 10% |
| rare | 25 | 2 | 25% |
| epic | 40 | 2–3 | 50% |
| legendary | 60 | 3 | 75% |
| Карточка заточки (уровень L) | `forgeBudgetPerLevel × L` | 1–3 | 40% |
| Трейт работника | по звёздам: 6 × звёзды | 1–2 | 30% |
| Трейт помощника | по редкости | 1–3 | 50% |

Пример заказчика: «покупаем кирку common — базовая сумма бафов 10, на неё надо набрать бафов». Кирка common → бюджет 10 → роллится 1 баф, скажем `oreYield` со стоимостью ≤ 10 → значение где-то в кривой, например +9% добычи (cost(9) ≈ 6.5) — остаток 3.5 слишком мал для нового бафа, и ролл фиксируется. Кирка rare → 2 бафа и, возможно, дебаф `energyCostRedution +12%` (штраф к расходу энергии), который вернёт бюджет и усилит бафы.

## 5. Алгоритм ролла

```
rollFor({ budget, scopeTags, rng, idPrefix }):
  1. candidates = типы реестра, чей scopeTags пересекается с scopeTags запроса
  2. nPos = rollRange(minPos, maxPos)        // из ModBudgetRule
  3. выбрать nPos разных типов бафов (взвешенно по costWeight)
  4. для каждого: роллить значение v так, чтобы cost(v) влезал в остаток бюджета
     (решение уравнения кривой стоимости — бинарный поиск по v)
  5. с шансом negChance добавить 1 дебаф: тип из maxNegative ≠ уже выбранным,
     значение роллится свободно (лимит — только кривая), costNegative идёт в рефанд
  6. если суммарная стоимость > бюджета — перегнать слабейший баф вниз (не пересборка)
  7. вернуть RolledMod[] с детерминизмом по сиду (rng передан снаружи)
```

Детерминизм: все роллы — через RngBus с сидом контекста (например `hash(saveId, itemId, attempts)` для реролла). Один и тот же сид — один и тот же ролл.

## 6. Реролл-цикл (как у ривенов Warframe)

Для стартовых роллов предметов (не для карточек заточки): `reroll(instance)` генерирует новый вариант РЯДОМ со старым; игрок выбирает: оставить новый или остаться на старом. Стоимость реролла растёт геометрически (×1.15 за попытку, кап ×10 базы) и сбрасывается при выборе. Реролл НЕ может понизить редкость предмета — бюджет фиксирован редкостью.

## 7. Карточки заточки — питатель M10

M10 при успехе заточки вызывает `rollFor` ТРИЖДЫ с бюджетом уровня → получает 3 карточки-кандидата, игрок выбирает одну (или отказывается за +2% pity). Карточка хранится в `ItemInstance.rolledMods` с `from: 'forge', forgeLevel: L`. Дебафы в карточках — осознанный дизайн заказчика: «карточки бывают и вредными» (пример: `maxDurability −5`).

## 8. Трейты работников и помощников

M11 и M13 генерируют профили: `traits: RolledMod[]` в бюджете звёзд/редкости (таблица §4). Трейт-модификаторы ложатся в шину, пока работник нанят и назначен на систему (провайдер работника — в M11). Генератор НЕ знает о существовании работников.

## 9. Интеграция

- API: `modforge.rollFor(req)`, `modforge.reroll(instance)`, `modforge.costOf(type, value)`.
- События: `modforge.rolled` (кто, бюджет, список роллов — для честного UI и логов).
- Debug: `mods list`, `mods roll <rarity> [tag]`, `mods cost <type> <value>`.
- Зависимости: только ядро (RngBus, реестр данных). M02/M10/M11/M13 — потребители через `ModuleRegistry`.

## 10. Приёмка и тесты

- [ ] Инвариант бюджета: монте-карло 10 000 роллов каждой редкости — ни одного перелимита (жёсткий тест).
- [ ] Рефанд дебафов: с дебафом сумма бафов в среднем выше на refundRate−1 (статистический тест).
- [ ] Детерминизм: один сид → один ролл, 1000 повторений.
- [ ] Реролл: стоимость растёт по формуле; выбор сбрасывает инфляцию.
- [ ] Расширяемость: тест-фикстура добавляет НОВЫЙ тип характеристики в реестр данными и роллит его — без изменения кода движка.
- Границы: применение роллов к статам — провайдер потребителя (M02/M11/M13); заточка и pity — M10.
