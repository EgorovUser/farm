### 3.5 Кривые стоимости (D35, D36): чистые функции в `logic/`
- `costOf(typeId, v)`: хорошая сторона → `round(costWeight × (|v|/|maxPositive|)^posExp × 100)/100`; плохая → `−round(costWeight × (|v|/|maxNegative|)^negExp × 100)/100`; рефанд дебафа = `|cost| × negativeRefund`. Экспоненты — по профилю `curve` типа из balance (D36).
- `valueUnderCost(typeId, budget)`: максимальное ЦЕЛОЕ v хорошей стороны с `cost(v) ≤ budget`; монотонность кривой → бинарный поиск по `[0..|maxPositive|]`; граничный инвариант: `cost(v) ≤ budget < cost(v+1)`.
- `mods cost <typeId> <v>` → полная раскладка (сторона, стоимость, |cost|, рефанд если дебаф); `mods cost <typeId>` без значения → кривая в 11 точках (0..maxPositive шаг |max|/10) — «числа на стол» (П6).

### 3.7 Selftest — группа «M03 Ривен-генератор» (часть 1, ≥10 проверок, оракулы руками)
1. Реестр валиден: zod; все id уникальны (snake_case), scopeTags непусты, costWeight > 0, границы ненулевые.
2. Битая фикстура ловится валидатором (негативная проба).
3. costOf: cost(0) = 0.00 и cost(|maxPositive|) = costWeight — по всем типам таблицей.
4. Монотонность хорошей кривой: ≥1000 псевдослучайных пар v1 < v2 → cost(v1) < cost(v2).
5. Форма кривых: cost(|max|/2) < costWeight/2 (суперлинейность); |cost(|maxNeg|/2)| > costWeight/2 (сублейнейность плохой).
6. Плохая сторона: |cost(|maxNegative|)| = costWeight; рефанд = |cost| × 1.25 (negativeRefund из данных).
7. valueUnderCost: ≥100 случайных бюджетов → граничный инвариант cost(v) ≤ b < cost(v+1).
8. Пример заказчика: costOf('oreYield', 9) = 6.55 (калибровка карточки §4).
9. Бюджеты: полнота byRarity (6 строк: 10/16/25/40/60/90); forgeBudgetPerLevel × L (L=1 → 2, L=10 → 20); трейт работника 6 × звёзды (1★ → 6, 5★ → 30); реролл: baseCost по редкости, инфляция ×1.15 за попытку до капа ×10, сброс при выборе.
10. П6-гигиена: rg-проба — числа не в логике.
