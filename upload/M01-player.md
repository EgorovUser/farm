# M01 — Игрок: энергия, HP, кошелёк, XP/уровень, навыки

> Фаза 1 · объём M · вход: 01-CORE, 02-BUSES, 03-DATA, этот файл. Зависимости: только ядро.

## 1. Цель модуля

Быть единственным владельцем «тела игрока»: энергии, HP, кошелька ресурсов, опыта и уровня, навыков от использования. Всё, что другие модули хотят списать или выдать игроку, идёт через TransactionService и события — сам кошелёк инкапсулирован здесь.

## 2. Энергия

- Базы в данных: `player.energy.max = 100`, `player.energy.regenPerMinute = 1/3` (1 ед / 3 мин), реген идёт и оффлайн (catchUp), но не выше капа.
- Кап растёт модификаторами: пассивки (`+20 flat` на пороге), «Кровать» (раз в игровой день бесплатный сон до капа — действие из данных), еда (`useAction` из M02 даёт `grantEnergy`).
- Расходы действий — статы вида `action.<system>.<verb>.energyCost` с базами в `content/balance/energy.ts`: вспашка 5, посадка 1, полив 2, прополка 1, сбор 3, заброс 4, кормление 1, вход в шахту 20, удар в бою 1, крафт 2, попытка заточки 3. Списание: `statBus.resolve('action.farm.plow.energyCost')` → TransactionService. Keystone «Спартанец» (M14) опустит всё это через `inc −50%` — модуль не узнает.
- Правило дизайна: энергия — темпоритм, не замок. Всегда есть занятия с нулевым расходом (магазин, приказы работникам, биржа), и еда.

## 3. HP

- Базы: `player.hp.max = 50`, реген вне шахты `1 / 5 мин`; в шахте НЕ регенится (родники/костры/зелья — M13).
- `useAction` лечит мгновенно. «Смерть» (HP = 0 в забеге): событие `player.hpChanged` с тегом `death` — M13 сам решает, что делать (вылет, потеря 20% рюкзака, HP = 1). M01 только хранит и репортит.

## 4. Кошелёк (ресурсы) и XP/уровень

- `wallet: Record<CurrencyId, number>` — золото, руды, материалы, хозяйство (`03-DATA §1`). Пополнение/списание ТОЛЬКО через TransactionService; событие `wallet.transaction` с раскладом. Для каждого ресурса в контенте — `sources/sinks` (данные для подсказок «где добыть»).
- **[УТОЧНЕНО 2026-10-22]** Физическое хранение кошелька — сервис ядрового слоя (срез `kernel.wallet`, сдан в Фазе 0 и заморожен вместе с TransactionService). Модуль M01 НЕ переносит срез и НЕ дублирует хранение: он владеет игровой семантикой кошелька — каталог валют и `sources/sinks` в контенте, публичный API грантов/списаний (обёртки над TransactionService), инвариант «ни один модуль не пишет в кошелёк напрямую» (§8). Ратифицировано по итогам аудита Фазы 0 + FIX-0.1.
- XP: за значимые действия, начисляется по событиям (таблица в данных: вспашка 2, сбор 5, рыба 8, крафт 10, моб 15, босс 100, квест 50–500). Уровень: `xpToNext(L) = 100 × 1.15^L`. Событие `player.levelUp` — на него подписаны пассивки (+1 очко, M14), гейты, UI.
- Уровень игрока — главный гейт разблокировок; проверяется везде через `Requirement`-оценщик.

## 5. Навыки от использования

- Список навыков в данных: Фермерство, Рыболовство, Рыбоводство, Животноводство, Крафт, Кузнечество, Горняк, Боец, Торговля.
- Механика: значимое действие публикует событие с тегом навыка (например `farm.cropHarvested` → `skill:farming`); SkillEngine по манифесту подписок добавляет XP. Заточка даёт опыт кузнечеству ДАЖЕ при провале — стаж есть всегда.
- `xpToNext(skillLevel) = 50 × 1.2^skillLevel`. Каждый уровень навыка — модификатор из `SkillDef.perks` (данные): «+5% эффективность смежных действий», каждые 5 уровней — перк-порог (шире зоны мини-игр, +1 слот грядки/озера на больших порогах, разблокировка локаций: навык 10 рыболовства открывает Реку).
- Все перки навыков — провайдер `skillProvider` в StatBus: сам модуль не раздаёт эффекты руками.

## 6. Счётчики ядра (stats)

Ядро ведёт `Record<counterId, number>` по событиям (конфиг счётчиков в данных): урожаи по типам, рыбы по видам, попытки заточки, успехи/откаты, забеги, боссы по типам, объёмы торгов. Потребители: квесты/ачивки (M15), биржевые тренды (M16), пассивные очки. Счётчик = данные (`{ id, event, filter }`) — на новую статистику код не пишется.

## 7. Интеграция (манифест)

- События публикует: `player.*`, `skill.levelUp`, `wallet.transaction` (гранты TransactionService читает).
- Провайдеры: `skillProvider`, `levelBonusProvider` (+HP/энергия за уровень).
- API: `player.spendEnergy`, `player.checkHp`, `player.addXp`, `skills.get`.
- Debug: `give`, `xp add <n>`, `energy set`, `skills list`, `stats show`.

## 8. Приёмка и тесты

- [ ] Ни один модуль не пишет в кошелёк напрямую (тест-шпион на wallet-объект).
- [ ] Реген энергии/HP в catchUp совпадает с ручным расчётом по фиксированным датам.
- [ ] XP-кривые и перки — из данных; тест уровня с 1 по 60.
- [ ] Энергия списывается один раз за действие, при отказе транзакции — откатывается.
- Границы: инвентарь — M02; ачивки — M15; объекты «сон/еда» — данные M02/M05.
