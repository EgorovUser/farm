## P0 — критичные

### A. Hydration-баг (живая находка: server `00:00:00` vs client `03:00:00`)
Причина: элемент с временем в шапке рендерится при SSR в таймзоне сервера (UTC), на клиенте — в локальной (Europe/Moscow). Любой вывод, зависящий от `now()`/`Date` в первом кадре, даёт hydration-mismatch.
Сделай: все now()-зависимые элементы UI — только после монтирования (`mounted`-флаг через `useEffect`), до этого плейсхолдер `--:--:--`. НЕ использовать `suppressHydrationWarning` как основное средство — он прячет настоящие расхождения.
Пройди поиском все компоненты и stores: `new Date`, `toLocaleTimeString`, `format*Time`, `now()` в начальном рендере — каждый такой вывод закрыть mounted-гейтом.
Приёмка: 3 жёсткие перезагрузки → 0 hydration-ошибок в консоли; время появляется после гидратации, плейсхолдер — до.

### B. Лента событий тонет в time.minuteTick (живая находка)
Тик каждую секунду — НЕ баг (02 §8: 1 игровая минута = 1 реальная секунда). Баг — UX: recent-лента (cap 100) полностью забивается тиками за ~100 секунд, прочие события не видны.
Сделай: фильтр СТРОГО отображения в панели ленты: по умолчанию `time.minuteTick` скрыт, остальное показывается; переключатель — команда `events ticks on|off` (+ кнопка в панели, если дёшево). Подписчики EventBus продолжают получать minuteTick (очистка кэшей шин зависит от него!) — фильтр живёт только в UI-слое.
Приёмка: `buy …` → в ленте видно `wallet.transaction`, а не стену тиков; `events ticks on` возвращает тики; resolve после mod add по-прежнему инвалидирован немедленно.

### C. Покрытие условий/тегов модификаторов (MISS-1 аудита)
Единственный содержательный пробел self-checks: `checkCondition` (03 §2) и тег/срок-фильтры не покрыты ни одной из 103 проверок.
Сделай: (1) новая группа self-checks «фильтры модификаторов», ≥10 проверок с ручными оракулами: ctxTag есть/нет; statAtLeast; statAtMost; `not`; `all`; `any`; hasItem/flag (если дёшево headless); мод с истёкшим `expiresAt` игнорируется; теги ctx сопоставляются по AND; неизвестный тип условия → false (01 П5). (2) Расширь `mod add` ключами `[prio=N] [group=X] [tag=T]` (суффиксами, как срок) — ручные пробы priority/stackGroup/тегов из консоли (MISS-5).
Приёмка: selftest ≥ 113, дважды идентично; живые пробы: два override prio 10 vs 5 → побеждает 10; два `inc 25` в одной группе → 125, в разных → 156.25; баф с `[tag=fishing]` не действует, когда тега нет в ctx.

### D. dailySeed-пересев (DEBT-1; классифицировано P0)
Сейчас сид шины = `hash(saveId)` навсегда, `RngBus.dailySeed()` без потребителей, а команда `time` печатает «ротации привязаны к дате» — ложный текст.
Сделай: при старте/загрузке сейва сид шины = `dailySeed(saveId, dateISO(now))`; подписка `time.dayTick → setSeed(dailySeed(...))` (в bootstrap, НЕ в ядре). catchUp-итерации dayTick пересевают так же — детерминированно по каждому пропущенному дню. Текст команды `time` сделать правдивым (или убрать фразу).
Приёмка: `time +1d` дважды → роллы одной таблицы идентичны; рестарт в тот же день → идентичны; смена дня → другие роллы; `catchup simulate 400` → роллы после досчёта соответствуют текущему дню.

## P1 — до M01

### E. Дробные статы (DEBT-6)
Дефолт `Math.round` искажает реген: база 0.5 → резолв 1 (ловушка M01).
Сделай: `Rounding += 'none'` (без округления) + StatMeta `round: 'none'` для `*.regenPerTick`; убрать пометку «*изменён» в stats.list там, где это чистое округление, а не модификатор.
Приёмка: `resolve player.energy.regenPerTick` = 0.5; selftest +2 (rounding none; база не искажается).

### F. Инвариант «суммарная скидка ≤ 90%» (DEBT-2)
`maxTotalDiscountPercent: 90` объявлен в economy.ts, но кодом не читается — инвариант 04 §4.1 держится случайно (капы групп 60/40 → макс 76%).
Сделай: прямой клэмп в PriceBus — эффективная суммарная скидка `1−(1−g)(1−l)` не выше `maxTotalDiscountPercent` ИЗ КОНФИГА; применение клэмпа видно в breakdown; self-check читает конфиг (убрать хардкод `0.099`) + монте-карло с временными капами 80/70 в данных ловит клэмп.
Приёмка: при капах 80/70 итоговая скидка ≤ 90% и цена ≥ `ceil(base × 0.1)` в 500 случайных комбинациях.

### G. Бафы kind:'runs' (DEBT-5)
`expiresAt = now + Infinity` → JSON `null` → после загрузки баф признаётся истёкшим и съедается sweep'ом. Ловушка M13.
Сделай: для `kind: 'runs'` НЕ выставлять expiresAt (отсутствие даты = «до конца забега»); фильтры и sweep уважают признак; очистку оставь будущему API M13 — сейчас не реализовывать.
Приёмка: self-check: runs-баф жив после save/load roundtrip; sweep его не трогает.

## P2 — до M02/M04

### H. Offset DebugClock в сейве (DEBT-4)
Живая находка аудита: `time +5h` → баф 10м → после F5 «осталось 605ч»: offset не сохранён, expiresAt записан в сдвинутом времени.
Сделай: срез `kernel.clock` (offset) в сейве; bump saveVersion 1→2 + миграция (нет среза → offset 0). Альтернатива — нормализация expiresAt при записи сейва: выбери сам, обоснуй [DECISION].
Приёмка: `time +5h` → баф 10м → `save` → F5 → «осталось» ≤ 10м; сценарий 605ч закрыт; сейв версии 1 миграцией поднимается до 2.

### I. Откат списаний в транзакции (DEBT-7)
Защитный отказ `items.remove` после частичного применения не откатывает списанное — контракт «байт-в-байт» (02 §9) нарушим при кривом порте M02.
Сделай: двухфазность — собрать план применения → применить все позиции → при первом же отказе вернуть уже применённое; события гранта не стреляют при откате. Self-check с порт-заглушкой, падающей на ВТОРОМ remove: состояние байт-в-байт прежнее.
Приёмка: self-check зелёный; обычные сценарии buy/sell не изменились; атомарность из §9 выполняется дословно.

### J. Команда save import (MISS-3, DEBT-11)
02 §11 декларирует импорт JSON, но он недостижим пользователем.
Сделай: `save import <json>` (вставка строки; file-input в панели — опционально). Валидация и миграции — как при обычной загрузке: версия 0 → мигрирует; из будущего → отказ; кривой JSON → внятная ошибка, текущее состояние не тронуто.
Приёмка: export → правка saveVersion на 0 → import мигрирует; на 99 → «версия из будущего»; битый JSON → ошибка без последствий.

### K. Вынос self-checks из kernel (DEBT-3)
`src/kernel/self-checks/` импортирует `@/game/bootstrap` и `@/content/**` — нарушение буквы 01 §5 («kernel не импортирует ничего выше себя»).
Сделай: перенести в `src/selfchecks/` (или `tests/runtime/`); импорты вверх остаются только там.
Приёмка: `rg "from '@/game|from '@/content" src/kernel/` — пусто; `selftest` работает из консоли как раньше.
