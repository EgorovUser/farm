# M02 — Инвентарь, экипировка, качество предметов

> Фаза 1 · объём M · вход: 01-CORE, 02-BUSES, 03-DATA, M01, этот файл. Зависимости: M01.

## 1. Цель модуля

Владеть экземплярами предметов: хранить, стакать, экипировать, продавать, расходовать. Быть провайдером модификаторов экипировки в StatBus. Роллы характеристик — НЕ здесь (генерирует M03), здесь только хранение и применение.

## 2. Слоты, стаки, вкладки

- Сетка: база 20 слотов (`player.inventory.slots`), расширение «Рюкзаками» (кожевенный крафт M09) и пассивками: +4 за шаг, кап 60. Стаки: семена/наживки/расходники/рыба — до 50 (апгрейд до 100); уникальное снаряжение не стакается.
- Вкладки по `itemType` — из данных (инструменты/снаряжение/расходники/прочее); категория новой вкладки = строка данных.
- Слоты экипировки (данные): Кирка, Оружие, Броня, Щит, Удочка, Активная наживка, Аксессуар ×2. Новые слоты (будущее) — без кода.

## 3. Действия над предметом

Использовать (consumable: `useAction`-эффекты через TransactionService/M01), Экипировать/снять, Продать (`priceBus.sellPrice` + TransactionService, событие `item.sold`), Заточить (вызов API M10, не импорт!), Разобрать (вернуть 25% ресурсов рецепта), Подарить (M16 через флаг тега `giftable`).

Гейты: использование/экипирование проверяет `ItemDef.requirements` (уровень, навык, ачивка, флаг). Нарушение — штатный отказ `Result` с причиной (UI покажет).

## 4. Качество, редкость, прочность

- `quality: { tier, value }`: тир D..SS, дробное 0..100 внутри тира для сверки цен. Для крафтового снаряжения тир пересчитывается от `sharpeningLevel` (M10: каждые 10 уровней = +1 тир). Для выпавшего/выловленного/выращенного — роллится при получении (RngBus, из данных таблицы).
- Сила статов и цены — множители тиров/редкости применяются К БАЗЕ шиной (П2): `base(price)` уже содержит множители, потребители про них не знают.
- Прочность: −1 за использование у tool/weapon/armor/shield/rod; при 0 предмет «сломан» (не работает, НЕ исчезает); ремонт на наковальне (M09) за 10% базовой цены. Прочность — поле экземпляра, НЕ модификатор.

## 5. Провайдер модификаторов экипировки

`equipmentProvider`: при резолве любого стата перечисляет экипированные `ItemInstance.rolledMods` (+ стартовые `baseStats` шаблона как flat-модификаторы с источником item) и отдаёт их шине. Смена экипировки → `invalidate.stat`. Так «меч +10% крита» влияет на бой (M12) без единого импорта между модулями.

## 6. Интеграция

- События: `item.acquired/consumed/equipped/sold` (в `item.acquired` — defId, качество, источник-тег: для квестов «поймай/вырасти/скрафти»).
- API: `inventory.add/remove/has`, `inventory.equip/unequip`, `inventory.list(filter)`.
- Debug: `give`, `inv list`, `inv equip <iid> <slot>`, `inv clear`.

## 7. Приёмка и тесты

- [ ] Экипирование предмета с роллом меняет `resolve` нужного стата (интеграционный тест с ядром).
- [ ] Гейт-требование блокирует экипировку и показывается причиной отказа.
- [ ] Стаки сливаются/делятся по правилам данных; переполнение — отказ, не потеря.
- [ ] Продажа идёт через PriceBus/TransactionService: событие `wallet.transaction` и `item.sold`.
- Границы: генерация роллов — M03; заточка — M10 (только через `ModuleRegistry.get('forging')`); UI — фаза 6.
