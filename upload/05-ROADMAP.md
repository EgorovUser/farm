# 05 — ROADMAP: план разработки по фазам

> Стратегия плана (по требованию заказчика): **сначала общие и самые важные механики без хорошего интерфейса** — ядро, шины, просчёты, экономика, — и только потом конкретный контент и красота. До фазы 6 интерфейсом служат debug-консоль (02-BUSES §12) и уродливые отладочные панели-таблицы. Каждая фаза завершается запускаемым состоянием с зелёными тестами.

## 1. Фазы

| Фаза | Что строим | Модули | Done-критерий фазы |
|---|---|---|---|
| **0. Ядро** | Шины, сервисы, контент-реестр, debug-консоль, сейв | 02-BUSES + 03-DATA (реализация ядра) | все тесты из 02-BUSES §13 зелёные; `resolve`/`price`/`roll` работают из консоли |
| **1. Игрок и вещи** | Игрок, инвентарь, ривен-генератор | M01, M02, M03 | из консоли: дать предмет, роллнуть моды, экипировать, увидеть изменение стата через resolve |
| **2. Экономика** | Магазин, крафт, заточка, квесты-ачивки | M04, M09, M10, M15 | цикл «купил семя → скрафтил кирку → заточил до карточек → продал» без UI |
| **3. Производство** | Ферма, загон, рыбалка, озеро, работники | M05, M06, M07, M08, M11 | конвейер ресурсов живёт 3 реальных дня без ручного участия (тик + catchUp) |
| **4. Рогалик** | Шахта: бой, карты, помощники, пассивки | M12, M13, M14 | цикл «руда → слиток → заточка кирки → новый слой» замкнут |
| **5. Мета** | Деревня, биржа, соц-заглушки | M16, M17 | дневной цикл деревни (потребности → налоги → биржа) сам себя окупает 30+ дней |
| **6. Интерфейс** | Панельный UI, мини-игры, полировка, баланс-проход | M18 + баланс всех | полный прогон всех систем «мышкой», без входа в debug-консоль |

Порядок фаз 0–2 менять нельзя. Фазы 3–5 можно переставлять местами ЦЕЛИКОМ (например, сначала рогалик, потом производство) — карточки модулей это допускают.

## 2. Карточки модулей (формат передачи в AI)

Общие поля каждой карточки: **фаза · зависимости · объём (S ≤ 1 сеанс, M ≤ 2–3 сеанса, L = разбит на подзадачи) · вход (какие файлы подать) · артефакты · приёмка · границы**. Объём L обязательно режется на подзадачи в первом сеансе модуля: AI выдаёт план подзадач, каждая подзадача = отдельный последующий сеанс.

---

### M01 — Игрок: энергия, HP, кошелёк, XP, навыки
Фаза 1 · зависит от ядра · **объём M** · вход: 01, 02, 03, M01
Артефакты: логика стата/энергии/HP/XP, SkillEngine, счётчики действий, debug-команды (`give`, `xp add`, `skills list`).
Приёмка: энергия/HP/кап читаются только через StatBus; навык растёт от событий; тест на формулы регена и XP; сейв-срез игрока.
Границы: инвентарь/экипировка — M02; никаких ачивок (M15).

### M02 — Инвентарь и предметы
Фаза 1 · зависит от M01 · **объём M** · вход: 01, 02, 03, M02
Артефакты: слоты/стаки/вкладки, экипировка, провайдер модификаторов экипировки, продажа через PriceBus, поломка/ремонт.
Приёмка: экипирование меняет resolve без правки чужого кода; требования-гейты (`Requirement`) блокируют использование; стаки и лимиты из данных.
Границы: роллы модов — M03; цены/скидки — только шина.

### M03 — Ривен-генератор (конструктор характеристик)
Фаза 1 · зависит от M02 (типы) · **объём L → 3 подзадачи** · вход: 01, 02, 03, M03
Подзадачи: (1) реестр ModTypeDef + кривые стоимости; (2) генератор роллов в бюджет (позитивы/негатив/рефанд); (3) реролл-циклы и API для M10-карточек.
Приёмка: бюджет любой редкости соблюдается инвариантом (монте-карло); общий движок используется для снаряжения, трейтов работников, помощников и карточек заточки без ветвления по «кто вызывает»; детерминизм по сиду.
Границы: сам генератор НИЧЕГО не знает о заточке/работниках — только `rollFor(budget, tags)`.

### M04 — Магазин с ежедневной ротацией
Фаза 2 · зависит от M01–M03 · **объём M** · вход: 01–04, M04
Артефакты: dailySeed-ротация (30% пула), скидочные слоты 5–50%, уровни/ветки прокачки, гейты ассортимента, сток/скупка через TransactionService.
Приёмка: ротация детерминирована (`shop.reroll` после `time +1d` совпадает); скидки — только через 04-DISCOUNTS; заблокированные товары видимы с условиями (данные для UI).
Границы: купоны/акции — не здесь.

### M09 — Крафт и верстаки
Фаза 2 · зависит от M01–M03 · **объём M** · вход: 01, 02, 03, M09
Артефакты: станции из данных, рецепты, очередь крафта, качество результата (формула §M09.4), мини-игра-хук с auto-режимом.
Приёмка: цепочки 2–4 шага; качество результата зависит от навыка и тира входов; неизвестные рецепты (гейт) не видны.
Границы: заточка — M10; UI-мини-игры — фаза 6 (auto-режим в тестах).

### M10 — Заточка (шанс, pity, откат, карточки)
Фаза 2 · зависит от M03, M09 · **объём M** · вход: 01, 02, 03, M10
Артефакты: шансы `base − decay×L + pityStep×fails`, откат, заморозка карточек при откате, выбор 1 из 3 карточек через M03, «10 уровней = +1 тир».
Приёмка: монте-карло-распределение исходов L0..L50; pity сбрасывается ТОЛЬКО при успехе; откат не зависит от попыток; карточки восстанавливаются при повторном достижении уровня.
Границы: сам ривен-ролл карточек — вызов M03.

### M15 — Квесты, ачивки, гейты
Фаза 2 · зависит от M01 · **объём M** · вход: 01, 02, 03, M15
Артефакты: движок условий (`Condition` из 03-DATA), счётчики ядра, daily (3 шт)/weekly (3 шт) из пулов по dailySeed, цепочки-шаги, ачивки с `unlockFlags`, движок наград.
Приёмка: прогресс трекается ТОЛЬКО по событиям; новые шаблоны квестов = данные; ачивка даёт флаг → гейт магазина/рыбы/слоя реально открывается (интеграционный тест с M04).
Границы: контент цепочек — добавляется фазами 3–5 по мере появления систем.

### M05 — Ферма
Фаза 3 · зависит от M01, M02, M09, M15 · **объём L → 3 подзадачи** · вход: 01, 02, 03, M05
Подзадачи: (1) модель вкладок/тайлов + FSM состояний; (2) часовые правила (сорняки, высыхание) + задачи TaskRegistry (water/weed/harvest); (3) урожай/качество/улучшения.
Приёмка: сорняки растут по `hourTick` и в catchUp; полив обязателен (сухая грядка на паузе); мини-игры — через контракт с auto-режимом; исполнители фермы регистрируются для работников.
Границы: работники — M11 (ферма их не знает).

### M06 — Загон (животные)
Фаза 3 · зависит от M01, M02, M15 · **объём M** · вход: 01, 02, 03, M06
Артефакты: покупка, кормление/чистота/гладить, продукция по часам, болезнь, разведение (формула потомства), улучшения.
Приёмка: склад продукции cap 3 сбора оффлайн; голодная скотина не производит; TaskRegistry-задачи `pen.*`.
Границы: ветеринария = крафт-лекарства (M09) и покупка (M04) — по данным.

### M07 — Рыбалка
Фаза 3 · зависит от M01, M02, M03 · **объём M** · вход: 01, 02, 03, M07
Артефакты: процесс заброс→клёв→подсечка (auto-режим), таблицы категорий дропа с весами, удача через RngBus, удочки/наживки/сокровищные удочки, гейтованные рыбы, альбом-коллекция (данные).
Приёмка: luck смещает таблицы (тест); рыба-гейт не попадает в пул без условия; события `fish.caught` несут все данные для квестов/альбома.
Границы: разведение — M08.

### M08 — Озеро
Фаза 3 · зависит от M07 · **объём M** · вход: 01, 02, 03, M08
Артефакты: слоты, температура/чистота с дрейфом, кормление/лечение/чистка, икра и потомство (мутация), био-конфликты улучшений.
Приёмка: формула потомства `max(родители) − 1 + мутация` покрыта тестом; больная/голодная рыба не размножается; задачи `lake.*`.
Границы: цены продажи — шина.

### M11 — Работники
Фаза 3 · зависит от M01, TaskRegistry-систем фазы 3 · **объём L → 2 подзадачи** · вход: 01, 02, 03, M11
Подзадачи: (1) доска объявлений (5/день по dailySeed), профили через ривен-трейты M03, найм/зарплата; (2) настроение/болезни/увольнения + WorkersDirector.
Приёмка: при нехватке денег увольняется РОВНО ОДИН случайный; микрошанс увольнения при настроении < 20 три дня; работники выполняют задачи ЛЮБОЙ системы только через TaskRegistry (интеграционный тест с фермой без импортов).
Границы: системы-работодатели не знают о работниках.

### M12 — Шахта: автобой в 3 направлениях
Фаза 4 · зависит от M01, M02, M03 · **объём M** · вход: 01, 02, 03, M12
Артефакты: раунд боя (атака/блок по направлениям, чутьё щита, «Вещий удар»), мобы/элиты/боссы из данных, HP-масштаб слоёв, дропы, смерть/отступление.
Приёмка: бой — чистая функция `(state, rng) → state` (тестируемость); блок при совпадении направлений; урон `atk×100/(100+def)`; боссы с фазами из данных.
Границы: карта забега/события — M13.

### M13 — Шахта: карточный рогалик + помощники
Фаза 4 · зависит от M12 · **объём L → 2 подзадачи** · вход: 01, 02, 03, M13
Подзадачи: (1) генерация слоя из колонок карт (скрытые/открытые, факел, атмосферные статусы, события); (2) помощники: профили через M03, страхи как `Condition`, репутация, доля награды.
Приёмка: сид слоя воспроизводим; факел вскрывает карту через luck; страх срабатывает как модификатор с условием (не ветвление в коде); runBag выдаётся на выходе.
Границы: сама боевая математика — M12.

### M14 — Дерево пассивок
Фаза 4 · зависит от M01, M15 · **объём M** · вход: 01, 02, 03, M14
Артефакты: узлы small/notable/keystone из данных, аллокация с рёбрами, провайдер модификаторов, респек за золото, очки от уровня/ачивок/боссов.
Приёмка: keystone реализуется ТОЛЬКО комбинацией модификаторов (override/inc/more) — без спец-кода; 150 узлов = данные без кода; респек возвращает очки и снимает модификаторы.
Границы: UI-зум дерева — фаза 6.

### M16 — Деревня и биржа
Фаза 5 · зависит от почти всех · **объём L → 3 подзадачи** · вход: 01–04, M16
Подзадачи: (1) жители/потребности/счастье/налоги; (2) здания и рейды; (3) биржа: контракты дня по dailySeed, тренды перепродажи, репутация партнёров.
Приёмка: налоги = `f(уровень деревни, среднее счастье)` через шину; рейд — сравнение защиты с порогом из данных, предвестник за 24 ч; биржевые цены через PriceBus с markup; помощь жителей — через TaskRegistry.
Границы: соц-онлайн — M17.

### M17 — Социальные механики (заглушки)
Фаза 5 · **объём S** · вход: 01, 02, M17
Артефакты: контракты (витрина фермы, подарки, лидерборды, кооп-счётчики) в данных + stub-интерфейсы, НЕ реализация.
Приёмка: схемы зафиксированы, сейв совместим; реализация отложена отдельной фазой с сервером.
Границы: никакого серверного кода.

### M18 — Панельный интерфейс и мини-игры
Фаза 6 · зависит от всех · **объём L → 4 подзадачи** · вход: 01, 02, M18 + модуль, чья панель
Подзадачи: (1) каркас: лента панелей, верхняя панель ресурсов, тёмная тема шахты; (2) MiniGameShell + 5 мини-игр (тайминг/ряды/струя/кликер/подсечка) с auto-режимом доступности; (3) тултипы модов, расшифровки цен/шансов, оффлайн-отчёт; (4) адаптив и полировка.
Приёмка: UI не содержит игровой логики (только вызовы публичных API и чтение шин); все шансы и расшифровки скидок видны; панель собирается из манифеста модуля (UiBinder).
Границы: логика — никогда в UI-слое.

## 3. Сквозные задачи (не модули, вплетаются по ходу)

1. **Баланс-проход** в конце каждой фазы: правка ТОЛЬКО `content/balance/` отдельным сеансом.
2. **Миграции сейва** — при любом изменении срезов (модуль сам пишет миграцию).
3. **Производительность тика** — после фазы 3: профилирование hourTick/catchUp, кэши шин.
4. **Проверка изоляции** — регулярно: скрипт линтера запретов импортов между `modules/*` (кроме `shared`, `kernel`).
